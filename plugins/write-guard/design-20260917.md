## 1. 需求背景

write-guard 目前只拦截"系统临时目录引用"（/tmp、\Temp、$TMP、%TEMP% 等）。
2026-09-17 实际发生两类未经授权的写入违规：

1. **未经用户授权覆盖 Hermes 配置**：`D:\myagent\.hermes\config.yaml` 及
   `profiles\<name>\config.yaml` 被直接覆盖（覆盖前只等了一次"是否覆盖"询问，
   未获明确授权即执行）。
2. **未经用户授权写入记忆库**：`hindsight_retain` 被直接调用，写入 hindsight 记忆，
   未获用户任何许可。

用户要求：在 write-guard 插件内**新增两个独立拦截项**，从机制上斩断上述行为。
临时目录拦截（现有逻辑）保持不变。

## 2. 目标行为

### 拦截项 A：Hermes 配置目录写保护

- **目标**：`D:\myagent\.hermes\` 下所有 `config.yaml`（含根目录与
  `profiles\<任意名>\config.yaml`）的**写入与修改操作**一律要求用户审批。
- **覆盖工具**：
  - `write_file` / `patch`：检查 `path` 参数是否指向受保护 config.yaml
  - `terminal`：检查 `command` 参数（cp/echo/tee/重定向等写操作路径）
  - 其他工具：兜底扫描全部字符串参数
- **命中动作**：`{"action": "approve", ...}` → 弹用户审批（与危险命令同一条
  审批通道，once/session/always/deny，超时 fail-closed 阻止）。
- **查询/读取不受影响**：读 config.yaml 不拦截（pre_tool_call 无法区分读写时，
  只拦截已知写工具与写命令形态；read_file / web / grep 类查询直接放行）。

### 拦截项 B：hindsight 写工具保护

- **目标**：`hindsight_retain`（唯一写入口）调用要求用户审批。
- **查询工具不管**：`hindsight_recall` / `hindsight_reflect` 等只读查询放行。
- **命中动作**：同 A，`{"action": "approve", ...}`。

### 拦截项 C（既有）：临时目录拦截 — 保持原样，不合并、不修改

## 3. 架构约束（用户明确指定）

1. **同一插件，独立函数**：三个拦截项各自独立实现，不得混在一个函数里。
2. **轮询调度**：`on_pre_tool_call` 是唯一入口，从上往下依次轮询三个拦截项，
   第一个命中的就返回，未命中继续下一个，全部未命中放行。
3. **互不干扰**：新逻辑不得附加/修改现有临时目录拦截逻辑；现有测试必须继续通过。

## 4. 源码机制依据（已从 hermes-agent 源码确认）

- `pre_tool_call` 插件 hook 返回 `{"action": "block", "message": ...}` → 直接阻止；
  返回 `{"action": "approve", "message": ..., "rule_key": ...}` → 升级到人类审批门。
  来源：`hermes_cli/plugins.py::_resolve_block_from_details()`，
  `tools/approval.py::request_tool_approval()`。
- `request_tool_approval` 走与 Tier-2 危险命令相同的门：允许列表、
  CLI 弹窗 / gateway pending、once/session/always/deny、超时 fail-closed。
  **LLM 无法绕过**；`rule_key` 控制 `[a]lways` 粒度（空则按
  `tool_name + reason hash` 独立持久）。
- 插件 hook 回调异常由 Hermes 自动捕获并记录，不影响主 agent；
  **approve 门本身异常时 fail-closed（block）**。

## 5. 设计

### 5.1 文件结构（保持现有）

```
write-guard/
├── plugin.yaml      # 不变（仍只注册 pre_tool_call）
├── __init__.py      # 不变（注册入口）
├── handler.py       # 扩展：轮询调度 + 三个独立拦截函数
├── deploy.py        # 已有部署脚本（不变）
└── test_handler.py  # 扩展：新增 A/B 拦截测试用例
```

### 5.2 handler.py 结构（新增部分）

```python
# ── 轮询入口（现有 on_pre_tool_call 改造为调度器）──
GUARDS = [
    _guard_tmpdir,      # C: 临时目录拦截（原逻辑原样迁移）
    _guard_hermes_config,  # A: 配置写保护
    _guard_hindsight_write, # B: hindsight 写保护
]

def on_pre_tool_call(tool_name, args, task_id="", **kwargs):
    """唯一入口：从上往下轮询所有守卫，命中即返回，全部放行返回 None。"""
    for guard in GUARDS:
        result = guard(tool_name, args, task_id)
        if result is not None:
            logger.info("write-guard: %s 命中，返回 %s", guard.__name__, result.get("action"))
            return result
    return None
```

每个守卫函数签名统一：`(tool_name, args, task_id) -> dict | None`，
返回 `{"action": "block"|"approve", "message": ..., "rule_key": ...}` 或 None。

- `_guard_tmpdir`：现有 `_scan` + block 逻辑整体搬入，**一行不改**。
- `_guard_hermes_config`：对写工具（write_file/patch/terminal 写形态）检查
  路径是否落在 `HERMES_CONFIG_DIR = r"D:\myagent\.hermes"` 下且文件名
  匹配 `config.yaml`（根目录或 profiles/<x>/config.yaml）。命中返回
  `{"action": "approve", "message": "…需审批…", "rule_key": "hermes_config_write"}`。
- `_guard_hindsight_write`：`tool_name == "hindsight_retain"` 即命中，返回
  `{"action": "approve", "message": "…需审批…", "rule_key": "hindsight_retain"}`。

### 5.3 判定细节（A 项写形态识别）

- write_file / patch → 只看 `path`
- terminal → 提取 command 中的路径 token（正则 `[\w:\\./]*(?:config\.yaml)`），
  规范化后判断是否在受保护目录内；同时识别写命令（cp/mv/tee/重定向 `>` 等），
  只对"写"形态拦截，读取命令（grep/cat/diff 等）放行。
- 路径大小写不敏感（Windows）；路径规范化用
  `os.path.normcase(os.path.normpath(...))` 比对前缀。

### 5.4 测试（test_handler.py 新增）

- A 项：write_file path=`D:\myagent\.hermes\config.yaml` → approve；
  `D:\myagent\.hermes\profiles\developer\config.yaml` → approve；
  terminal `cp x D:\myagent\.hermes\config.yaml` → approve；
  read 形态 `grep model D:\myagent\.hermes\config.yaml` → 放行；
  workspace 路径 → 放行。
- B 项：`hindsight_retain` → approve；`hindsight_recall`/`hindsight_reflect` → 放行。
- C 项：现有全部用例继续通过（回归）。

## 6. 部署与生效

- 改完运行 `python deploy.py` 同步到 `~/.hermes/plugins/write-guard/`。
- **重启 Gateway 生效**（插件代码改动不热加载）。
- 生效前提：插件已启用（`plugins.enabled` 含 write-guard，需确认现状）。

## 7. 风险与取舍

- **approve 审批的弹窗位置**：取决于当前审批 transport（CLI 弹窗 / gateway
  pending 卡）。若用户在 Slack/Feishu 侧，需确认审批卡能送达该渠道；
  若默认 transport 不支持，需另配 approval transport（二期，本次不做）。
- **terminal 写形态误判**：为降低误拦，只对"路径以 config.yaml 结尾且在
  保护目录内"的写命令形态拦截；无法 100% 识别所有 shell 写技巧，这是
  静态拦截的固有边界。
- **rule_key 语义**：A/B 各用一个固定 rule_key，用户选"always"后该拦截项
  永久放行；若需更细粒度（每次不同原因都问），可去掉 rule_key 或按原因哈希。

## 8. 验收标准

1. `python test_handler.py` 全部通过（含新增 A/B 用例与 C 回归）。
2. 部署后重启 Gateway，`/plugins` 显示 write-guard 加载正常。
3. 实测：让 agent 尝试 `write_file D:\myagent\.hermes\config.yaml` →
   弹审批；批准前工具不执行；拒绝/超时 → block。
4. 实测：`hindsight_retain` → 弹审批；`hindsight_recall` → 直接放行。
