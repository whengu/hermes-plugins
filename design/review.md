## 2. Findings 清单

### MED（3 条，实现前必须落实的设计修订，不改变架构）

**MED-1 — §3.1.2 伪代码 `home + os.sep` 与归一化正斜杠不一致，照抄则 A 项前缀判定全失效**
- 位置：§3.1.2 `_is_protected_config` 伪代码 `norm_target.startswith(home + os.sep)`；§3.1.3 步骤 3（分隔符统一为 `/`）。
- 问题：`_hermes_home()` 返回归一化结果（全正斜杠，如 `d:/myagent/.hermes`），而 Windows 下 `os.sep` 为反斜杠 `\`，`home + os.sep` 产生混合分隔符前缀（`d:/myagent/.hermes\`），与全正斜杠的 `norm_target` 前缀比对恒不相等 → A 项所有命中判定静默失败（fail-open 方向，配置写保护整体失效）。虽然 TC-A-01~04 会在测试期立即暴露此缺陷，但设计文档存在内部自相矛盾，违反"无歧义可直接照做"。
- 建议：定义统一分隔符常量（如 `_SEP = "/"`），伪代码改为 `home + _SEP`（或 `home + "/"`），并加一句"归一化后所有前缀拼接/比较一律使用正斜杠，禁用 os.sep"。

**MED-2 — 归一化未处理连续反斜杠/字符串转义，常见 Windows 路径书写形态漏拦**
- 位置：§3.1.3 步骤 3（反斜杠→正斜杠后未压缩连续分隔符）；§3.2.3（路径实参提取后直接归一化，未做 Python 字符串字面量解义）。
- 问题：execute_code 中 Windows 路径的标准写法是 Python 普通字符串转义形态，如 `open("D:\\myagent\\.hermes\\config.yaml", "w")`；terminal 中双引号命令也可能出现 `\\`。归一化步骤 3 仅逐字符 `\`→`/`，双反斜杠变 `//`，归一化结果为 `d://myagent//.hermes//config.yaml`，与基准 `d:/myagent/.hermes/` 前缀比对失败 → 漏拦。该形态是**静态可明确识别**的写形态（非"无法判定"），属 FR-02④/FR-04 覆盖完备性缺口；现有测试无此形态用例，漏拦静默。
- 建议：归一化步骤增加"连续反斜杠压缩（`\\`→`\`）"或"按 Python 字符串字面量解义（`\\`→`\`、`\n` 等转义序列解义后再归一）"；补用例：TC-A-43 `open("D:\\myagent\\.hermes\\config.yaml","w")` → approve、terminal `echo hi > "D:\\myagent\\.hermes\\config.yaml"` → approve；并补入风险表 R10。

**MED-3 — 环境变量展开函数语义未定义（大小写行为/变量名边界），大小写变体引用可能漏拦**
- 位置：§3.1.3 步骤 1（"由展开函数处理"未指明实现与语义）。
- 问题：若实现采用 `os.path.expandvars`，其对 `%VAR%`（Windows 语义）大小写不敏感、对 `$VAR`（POSIX 语义）**大小写敏感**——`$HERMES_home/config.yaml`（小写变体）不展开 → 归一化后不在受保护集合 → 放行绕过；`%hermes_home%\config.yaml` 则正确展开，行为不一致。设计未定义展开函数的变量名边界（`$HERMES_HOME2` 是否误匹配）与大小写语义，实现者行为不可预期；FR-04 类③的完备性有缺口，现有 TC-A-09~12 未覆盖大小写变体。
- 建议：显式定义展开语义（统一按 Windows 环境变量大小写不敏感查找；变量名边界正则明确）；补用例：TC-A-44 `%hermes_home%\config.yaml`、`$HERMES_home/config.yaml`、`${HERMES_home}\config.yaml` → approve；并补入风险表 R11。

### LOW（5 条，非阻断，可选）

**LOW-1 — write_file/patch 相对路径基准假设未对照 Hermes 实际语义核实**
- 位置：§3.1.3 步骤 5（"其余为进程当前工作目录"）。
- 问题：Hermes write_file/patch 对相对路径的实际解析基准（进程 cwd？workspace？会话目录？）未经源码核实即假设为进程 cwd；若实际基准不同，相对路径判定可能漏拦或误拦。
- 建议：实现期对照 Hermes 源码核实 write_file/patch 相对路径基准并写注释；无法核实时并入未决项或标注假设（相对路径写受保护目录场景罕见，Q-03 兜底，故 LOW）。

**LOW-2 — FR-06"完整路径"与"展示用户输入原文"的张力**
- 位置：§3.3 message 说明（DR-16）。
- 问题：等价类变体命中时（相对路径 `config.yaml`、环境变量引用 `%HERMES_HOME%\config.yaml`、cd 链形态），消息展示原文不含解析后的真实绝对路径，用户难以据此判断实际将被写入的文件，FR-06"完整路径"字面未完全满足。
- 建议：变体命中时消息采用"原文（归一化后：<真实绝对路径>）"双段展示；TC-M-01 相应扩展一条变体断言（TC-M-08）。

**LOW-3 — `_judge_path_param` 对非字符串/缺失 path 的防御行为仅由 TC-A-05 隐式定义**
- 位置：§3.2.1（`_judge_path_param` 只出现名字，无行为伪代码）。
- 问题：TC-A-05 已定义"非字符串/缺失 → 放行（None）"，但判定函数本身未给出一行防御说明，实现者需自行推断（如 `path` 缺失时 `args.get` 返回 None → 需判 None 后放行，否则可能抛异常被项级隔离兜住——行为仍为放行但不优雅）。
- 建议：在 §3.2.1 补一行：`path 非字符串或缺失 → return None`。

**LOW-4 — AC-04 的 read_file 放行无显式用例**
- 位置：§7.2。
- 问题：AC-04 要求 read_file 读受保护 config 放行；设计依赖"read_file 不在扫描集 → 放行"，仅由 TC-S-03 泛指覆盖，无显式断言用例，回归保护不足。
- 建议：补 TC-A-45：`read_file path=D:\myagent\.hermes\config.yaml` → None（放行）。

**LOW-5 — 复制至"受保护目录形态目标"的落盘形态未覆盖**
- 位置：§3.2.2 复制矩阵（"最后一个路径参数为目标"）。
- 问题：`cp config.bak D:\myagent\.hermes\`（目标为目录 + 尾斜杠）或 `cp -t` / `install -t` 形态：受保护路径按目录本身判定（norm == home → 非保护文件）→ 放行，但实际落盘为目录内 `config.bak`（含 config 子串，属受保护命名文件）→ 漏拦。属静态识别边界的细化遗漏，非最低强制集要求。
- 建议：矩阵补一句边界声明或规则——复制目标为受保护目录时按"源文件名落盘"再判定；或显式声明该形态属 OOS-03 静态边界不识别，二选一即可。
