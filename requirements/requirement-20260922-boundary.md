# 增量需求：terminal 检查的显式边界（用户决策 2026-09-22）

> 用户原话：「对终端工具的内容的检查这个不必考虑太复杂的情况，毕竟我们不是做一个
> 像 360 杀毒软件那样的安全管家软件，明确边界。」

## 定位

守卫目标是**拦掉"无心之失与朴素绕过"**，不是对抗国家级红队。凡是要专门研究
shell 语法冷知识才能构造出来的形态，不在防御义务范围内。

## 纳入范围（必须防，检出=缺陷必修）

1. 单行常规命令：重定向 `> >>`、tee、sed -i、dd of=、curl -o、cp/mv/install 常规位参；
2. 常规链式：`;`、`&&`、`||`、管道、裸换行/`\n`/`\r\n` 分隔、单反斜杠+换行续行；
3. 整词引号形：`"..."` / `'...'` 包裹路径、选项（如 `cp '-t' <dir> x`）；
4. 常规选项粘连：`-t<dir>`、`--target-directory=<dir>`、`-o<file>`；
5. 解释器内嵌一层（`bash -c "…"`、`cmd /c …`、pwsh -Command）与 execute_code 里
   os.system/subprocess 常见调用形；
6. 大小写命令词、Windows 正反斜杠、无尾分隔符目录目标（同语义必防）；
7. 复制/写入目标是守卫目录本体或 home 内配置/插件文件。

## 排除范围（登记为接受边界，检出≠必修）

1. **引号穿插/半混形**：`cp -'t'DIR`、`-"target-directory"`、逐字符拆引号
   `'-t'-`——构造需要词法层知识；**整词包裹**（`cp '-t' DIR`、引号包路径）
   仍在纳入范围，两者以"引号是否被劈开一个 token"区分；
2. **反斜杠奇偶算术族**：`\\`+LF、3 反斜杠+LF、引号内 `\`+LF、双引号内反斜杠
   仅对 `$ " \` 生效的转义表——POSIX 冷知识，人类手写命令不会这么写；
3. 变量间接展开（`a=cp; b=-t; $a $b DIR`）、eval 套壳（N-7）、heredoc 内嵌脚本
   深递归、tar/ln/robocopy/xcopy 专属语义（均已有登记）；
4. 多解释器嵌套（bash 套 powershell 套 cmd）、编码混淆（base64 管道回连）。

## 判级流程（后续每轮复审适用）

- finding 形态属**纳入范围** → 缺陷，修；
- 属**排除范围** → 写入 CHANGELOG「接受边界」节 + 回归用例锁当前行为，**不修**；
- 灰区（介于常规与 exotic 之间）→ 按"5 行内可修且不引入新解析层"标准裁决；
- 不再以"存在任何绕过"作为 CHANGES REQUIRED 的充分条件——收敛判据改为：
  **纳入范围内零缺陷 + 排除项全部登记在案**。

## 对当前轮次的影响

- F-7-2b（引号穿插 cluster）、F-7-1b（反斜杠奇偶族）→ 降级为排除范围，登记；
- F-7-2（`'--target-directory'=`）→ 灰区：若现有提取链一行可及则顺手修，
  否则登记，**禁止**为此引入引号剥离通用机制；
- **F-7-1 真续行**（`\`+LF，纳入范围第 2 条）→ 仍是必修缺陷；但修法按
  "简单可靠"优先：盲 replace 换行族 + 引号感知兜底只做到"行内引号成对校验"
  一层，不实现完整词法状态机。
